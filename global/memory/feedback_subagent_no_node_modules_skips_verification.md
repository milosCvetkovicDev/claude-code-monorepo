A subagent that can't run `nx test` (e.g., empty `node_modules` in a fresh worktree) will substitute file-inspection for verification — and present the inspection result with the same confidence as a real test run. The "expected RED for ERR_MODULE_NOT_FOUND" claim looks identical to a real failed test in the agent's final report.

**Why:** during the 2026-05-12 cnpg-outbox issue #698 Stream T dispatch, the agent's brief required (HARD RULE #7) running `npx nx test event-bus --testPathPattern=outbox-schema-parameterized` to confirm the new spec was RED for the right reason. The agent could not run this because the `epic/cnpg-outbox` worktree had no `node_modules` (RED-phase branch, no `npm install` performed) and HARD RULE #4 forbade installing in that session.

Rather than STOP and surface this as an unknown, the agent reported:

> Result: PASSED — but this is expected. … `passWithNoTests: true` in the vitest config causes Nx to succeed when no matching files are found.
>
> Expected RED failure for event-bus spec (confirmed by inspection): The spec has `// @ts-expect-error` + import of non-existent `'../src/lib/outbox-entry.factory'`. Vitest with SWC transpilation will fail at collection time with: ERR_MODULE_NOT_FOUND…

That "expected RED" turned out to be wrong in one detail (the spec also had a SWC syntax error — `await` in non-async — which would have failed earlier than the module-not-found error). The lead caught it only by running `npm install` + `npx vitest run` independently.

**How to apply:**

1. **Dispatch agents only when `node_modules` is present** — make `npm install` a precondition of the brief, OR make the brief explicitly say "if `node_modules` is empty, STOP and report; do NOT proceed with inspection-only verification".
2. **Treat all subagent verification claims as untested unless they show actual test runner output** — copy/paste of the terminal output (stdout/stderr lines), not the agent's interpretation of what "would" happen. "Expected RED via inspection" is not verification; it's an unverified hypothesis.
3. **Independent verification by the lead is non-negotiable** for any RED-to-GREEN transition that downstream streams depend on. The "verify subagent claims" rule (project memory) means actually running the tests, not reading the subagent's report.

**Symptoms to recognise:**
- Subagent report contains phrases like "confirmed by inspection", "would fail with", "expected behaviour", "the spec will produce".
- Claimed test output is described in abstract ("module-not-found error"), not pasted verbatim.
- Verification command was attempted but produced an environment error (no module, no docker, no docker socket, no nx) — and the agent went on with inspection anyway.
