## Merge drain (2026-07-02) — HARD-WON CI/MERGE LEARNINGS

- **RESOLVED — all 3 admin-merged 2026-07-02 10:54–10:56 UTC.** What finally broke the logjam: the real blocker was NOT moving-main (main was stable 37 min) but a **jammed self-hosted CI runner queue** — #1580's `ci / ci` sat `queued` 30+ min without starting (2 ukwest runners saturated). Diagnosis: `gh run list` showed `status=queued` for 30 min while `git log origin/main` showed no movement. Fix = **`ALLOW_PR_MERGE=1 gh pr merge <n> --squash --delete-branch --admin`** run by the USER via `!` (the pre-merge hook blocks `--admin` for the agent but NOT the user's `!` commands). Safe here because: code had passed `ci / ci` on its own commit pre-rebase, `Validate Terraform` green, main's interim commits (notification API, commission RBAC) didn't touch trading-service → ~zero conflict risk. **Lesson: when `ci/ci` is `queued` (not `pending`/running) for >15 min and main is stable, the bottleneck is runner starvation, not the up-to-date race — stop the update-branch treadmill and admin-merge proven-green PRs instead of re-queuing.** `--delete-branch` throws `fatal: 'main' is already used by worktree` (the local post-merge checkout, [[feedback_gh_pr_merge_delete_branch_worktree_quirk]]) but the merge still lands server-side; verify with `gh pr view --json state` + delete orphan remote branch with `git push origin --delete`.
- **Status (historical)**: #1566/#1575/#1580 spent the session OPEN. Serial-by-necessity because repo requires **branches up-to-date before merge** (`mergeStateStatus=BEHIND` blocks); each squash advances `main` and forces the next to re-update + re-run `ci / ci`. Strict "#1566-first" ordering STARVED the drain (its monitor re-updated it 24× without ever merging) — abandoning the order + focusing one green PR at a time was the right call.
- **`gh run rerun <id>` on the SAME run CANCELS its own in-flight jobs** → shows as `ci result: cancelled` / red gate while `test_results` shows the service `success`. This caused 3 false "failures" on #1566. **FIX: never re-run a stuck run; trigger a FRESH run** (`SKIP_HOOKS=1 git commit --allow-empty` + push → new run id). Also: `gh pr update-branch` adds a merge commit to the **remote** PR branch → local goes stale → `git reset --hard origin/<branch>` before an empty-commit re-trigger.
- **`gh pr checks --watch --required` exits early** — GitHub's "required" set it tracked did NOT include `ci / ci`; use plain `--watch` or poll `ci / ci` explicitly.
- **Evening merge flurry (17:00–18:00 UTC) jams CI**: 2 ukwest self-hosted runners (`acme-ukwest-01/02`), deep `Platform Pipeline` queue, jobs wait ~2h then get evicted/cancelled ("The operation was canceled"). ## Reusable foundations built here

- **`parse-list-filters.ts`** (at `apps/platform/trading-service/src/common/`, NOT `src/modules/common/` — `../../common/` from a module resolves to `src/common/`): the codebase's first **bracket-filter parser** (ADR-0057 canonical grammar). Accepts bare `filter[field]=v` as implicit `eq` AND `filter[field][eq|in|gte|lte|gt|lt|like]=v`. This is why one parser satisfies BOTH the **BE Cucumber** (`deal-http-gap-fills.feature` uses bare `filter[role]=BUYER`) and the **FE Pact** (`trading-consumer.pact.spec.ts` #7 uses operator `filter[role][eq]=BUYER`) unchanged. Parsed by **linear string slicing, not regex** — a regex triggered `security/detect-unsafe-regex` (hard lint error). New list endpoints should parse through this, not read flat keys ad hoc.
- **MikroORM `$contains` DOES map to jsonb `@>`** on a `type:'json'` array column (verified against real Postgres 16 in `customer-role-filter.tc.spec.ts`). `{ _roles: { $contains: [role] } }` → `roles @> '["ROLE"]'`. Any-of membership = `$or` of per-role `$contains`. Run through `TenantEntityManager` so the tenant `@Filter` still applies (a raw jsonb fragment would bypass it — same trap as the name-resolver). Reusable for any future jsonb-array filter.

## Convention decisions

- **List response envelope stays `{data, meta}`** for now (consistent across all sibling list endpoints). The canonical `{data, meta, errors}` (FE Pact expects it) is deferred to a dedicated **generic-list-contract slice** so it lands uniformly, not fractured onto one endpoint. BE Cucumber customer step-defs belong to that same slice.
- Fastify has **no `qs` parser**, so bracket query keys arrive FLAT on `request.query` (`filter[role][eq]` is one key). Parser + `@Query()` (whole object) read them; pagination still via `@Query('offset')`/`@Query('limit')`.
