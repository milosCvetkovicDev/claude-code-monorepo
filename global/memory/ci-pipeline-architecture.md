CI/CD pipeline architecture and optimizations applied March 2026.

**Why:** Pipeline was underutilizing the 8-core self-hosted VM and fallback path had redundant `npm ci` across 4 frontend shards.
**How to apply:** Reference when debugging CI, adding new apps, or making pipeline changes.

## Self-Hosted Runner

- **VM:** `Standard_D8as_v5` (8 vCPU, 32GB RAM, AMD EPYC) in `development-acme-rg`
- **Name:** `development-acme-runner`, label: `[self-hosted, ubuntu-latest-4-cores]`
- **Cost:** ~$137/month with auto-shutdown at 17:00 UTC
- **Auto-start:** `runner-auto-start.yml` cron at 06:00 UTC Mon-Fri
- **On-demand start:** `start-runner` job in CI does `az vm start` if VM is off
- **Network:** Subnet `10.0.3.0/28`, NSG denies port 5432 (can't access DB directly)
- **Cloud-init:** Node 22, Bun 1.1.45, Docker, GitHub Actions runner binary
- **Registration:** Manual one-time step via `az vm run-command invoke`

## Nx Remote Cache Server

- **App:** `nx-cache-server-bun` (Bun + Elysia), deployed at `development-acme-bun-nx-cache`
- **URL:** `https://development-acme-bun-nx-cache.acme-env-ci.uksouth.azurecontainerapps.io`
- **Storage:** Azure Blob Storage (`devacmenxbun`) + L1 in-memory LRU cache (100 entries, 500MB max)
- **Blob lifecycle:** Auto-delete after 14 days
- **Auth:** Dual-token — `NX_CACHE_READ_TOKEN` (PRs) and `NX_CACHE_WRITE_TOKEN` (main pushes only)
- **Tokens:** Generated by Terraform `random_password`, stored as Container App secrets
- **Read token:** Retrieved via `terraform output -raw nx_cache_read_token` from `infra/environments/development`
- **Security:** Timing-safe comparison (`crypto.timingSafeEqual`), 100MB max artifact, 1000 req/min rate limit
- **Cost:** ~$5-7/month (0.25 CPU, 0.5Gi, min 1 replica)
- **Health probe:** `GET /health/live` with 5s timeout (non-blocking — falls back to local cache if unreachable)
- **Protocol:** Nx built-in `NX_SELF_HOSTED_REMOTE_CACHE_SERVER` env var
- **Deploy:** `nx-cache-server-bun.yml` — builds Docker image on main push, deploys to Container App

## CI Pipeline (`ci.yml`)

### Primary path (self-hosted):
- `start-runner` → `main` (15 min timeout)
- `NX_PARALLEL=6` for better task graph execution on 8-core VM
- `NODE_OPTIONS=--max-old-space-size=8192`
- Runs: `nx affected -t build,test:unit` + `nx affected -t test` (excludes legacy-api integration tests)
- Local `.nx/cache` persists on VM disk across runs

### Fallback path (hosted runners):
- `fallback-main` (30 min timeout) → `fallback-frontend-tests` (4 shards, 20 min each)
- `node_modules` cached via `actions/cache` (key: `node-modules-<os>-<lockfile-hash>`)
- Shards reuse `node_modules` from `fallback-main` — skips `npm ci` on cache hit
- `.nx/cache` also cached via `actions/cache` (key: `nx-<os>-<ref>-<lockfile-hash>`)

### Integration tests:
- Run on main pushes OR PRs with `run-integration` label
- Label auto-added by `label-critical.yml` when `apps/legacy-api/src/` or `libs/` change
- Uses Postgres 15 service container + Azurite Docker container
- 45 min timeout

## Optimizations Applied (March 2026)

1. **`NX_PARALLEL=6`** in `main` job — doubles concurrent Nx tasks on 8-core VM
2. **`node_modules` cache** in fallback path — eliminates 4x redundant `npm ci` in frontend shards
3. **`cache: true`** on `domain-api` and `nx-cache-server-bun` build targets — `nx:run-commands` doesn't auto-cache via `targetDefaults`
4. **Auto `run-integration` label** — backend/libs changes auto-trigger integration tests
5. **Pre-push remote cache** — hook sources `~/.acme/nx-cache.env` for instant cache hits locally

## Local Developer Setup

To enable Nx remote cache in pre-push hooks, create `~/.acme/nx-cache.env`:
```
NX_SELF_HOSTED_REMOTE_CACHE_SERVER=https://development-acme-bun-nx-cache.acme-env-ci.uksouth.azurecontainerapps.io
NX_SELF_HOSTED_REMOTE_CACHE_ACCESS_TOKEN=<read-token-from-terraform-output>
```
Get the token: `cd infra/environments/development && terraform output -raw nx_cache_read_token`

## Build Caching Strategy

| Target | Executor | Cache | Inputs |
|--------|----------|-------|--------|
| `test` | varies | `targetDefaults` | `default`, `^production` |
| `test:unit` | varies | `targetDefaults` | `default`, `^production`, excludes integration |
| `test:integration` | varies | `targetDefaults` | `default`, `^production`, integration only |
| `build` (legacy) | `@nx/webpack:webpack` | `targetDefaults` | `production`, `^production` |
| `build` (legacy-web) | `@nx/vite/plugin` | plugin-inferred | auto |
| `build` (commission) | `nx:run-commands` | explicit `cache: true` | `production`, `^production` |
| `build` (nx-cache) | `nx:run-commands` | explicit `cache: true` | `production`, `^production` |
| `lint` | `@nx/eslint:lint` | plugin-inferred | auto |

Global cache invalidation: bump `.github/ci-cache-version.txt` (currently `1`).

## Platform Deploy Pipeline (AKS + ArgoCD)

Separate from the legacy deploy pipeline. Platform services deploy to AKS via ArgoCD.

**Deploy mechanism:** `kubectl patch application "platform-${svc}" -n argocd --type=merge` — sets `spec.source.helm.parameters` for `image.tag` and `environment`. No git-commit-based GitOps; CI patches the Application CRD directly.

**ApplicationSet:** Uses `ignoreApplicationDifferences` on `spec.source.helm.parameters` to prevent ArgoCD reconciliation from reverting CI-patched image tags.

**Rollback:** Same `kubectl patch` approach. History queries live cluster state (not a log file).

**Audit trail:** GitHub Deployments API + workflow step summaries. Replaced the previous `deployments.log.json` file-based approach.

**Deny windows:** ArgoCD AppProject deny windows use `manualSync: false` — blocks automated sync but allows manual emergency syncs.

**ArgoCD Image Updater:** Intentionally dormant. CI manages image tags directly via `kubectl patch`.

**Workflows:** `platform-deploy.yml` (deploy), `platform-rollback.yml` (rollback), `platform-build-push.yml` (build + push to GHCR).
