**PR #1466** (`feat/platform-frontend-same-origin-deploy`, base main) = the **deploy MECHANISM** for the platform-frontend dev deploy. Resolves "item 2" of [[platform-frontend-ui-adoption-epic]] (#1383/#1394 AC-8) and is the vehicle for the #1430 api-prefix epic's **#1438** exit gate.

**Why not SWA:** reverted #1440's Azure Static Web App scaffold — (a) a cross-origin SWA breaks auth (the FE has no CSRF token; `client.ts` relies on `SameSite=Strict` cookies, NOT sent cross-site), (b) wrong location (legacy `infra/environments/development/`; Platform is charts/ArgoCD). The revert (commit on the branch) also removed the Entra-SWA redirect append.

**Design (same-origin behind the gateway ingress):** `apps/platform-frontend/Dockerfile` (multi-stage nx build → **nginx, SHA-pinned** `nginx-unprivileged:1.27-alpine@sha256:28d91b…`) serving **static-only** (SPA fallback + /healthz, NO /api or /auth proxy). A minimal **custom** `charts/platform-frontend/` chart (NOT platform-base — that's NestJS-shaped) renders Deployment + Service + a **catch-all Traefik IngressRoute** (`Host(platform-dev.acme-example.net)`, explicit `priority:1`) + 2 Middleware (compress, security-headers; **CSP deliberately TODO** — a blind strict CSP breaks the SPA) + PDB(minAvailable 1, replicaCount 2) + default-deny NetworkPolicy. Traefik routes the more-specific `/api/v1` → gateway (API **and** auth, after #1452 moves auth under /api/v1), catch-all → the SPA. Relative `/api/v1` + SameSite cookies then work with **zero app changes**.

**Deploy = deliberate FINAL step (not on merge):** the standalone `charts/argocd/platform-frontend.yaml` Application is **MANUAL sync** (no `automated`). Merging #1466 STAGES it OutOfSync without deploying. The real deploy = a deliberate ArgoCD sync **once #1431 (MUI→kit) AND #1452 (api-prefix, epic #1430) have merged and the image is built** — that one sync then satisfies #1438 + #1394 AC-8 → smoke → **the human acceptance sign-off**. No `terraform apply` (AKS/ACR/DNS already exist; pure GitOps).

**POST-MERGE BUILD FIX (PR #1467, root-cause not band-aid):** #1466's fresh `platform-frontend` image red-ed main's `_build-push` at `COPY .eslintrc… .prettierrc .prettierignore ./` → `failed to compute cache key: "/.eslintrc.platform.json": not found`. **Latent fleet-wide bug, NOT frontend-specific:** root `.dockerignore` has EXCLUDED `.eslintrc*`/`.prettierrc`/`.prettierignore`/`.eslintignore` since #215 (Mar 27), yet BOTH `apps/platform/Dockerfile:75` (all 14 NestJS svcs) and the new frontend Dockerfile `COPY` those root configs (the Nx graph needs `.eslintrc.platform.json`, extended by `libs/platform/ui/.eslintrc.json`, #1353/#1398). The COPY only ever resolved off the **GHA Docker-layer cache**; the 14 NestJS images never re-ran it uncached, so it stayed masked — the brand-new frontend image was the **first uncached execution** → first to fail. **GENERAL LESSON: a `.dockerignore` that excludes a file a Dockerfile `COPY`s is a cache-masked landmine — only a fresh/`--no-cache` build trips it; it would have broken all 14 NestJS builds on the next `ci-cache-version.txt` bump.** Fix = **delete the exclusion lines** (a `!`-negation does NOT survive CI's shared BuildKit daemon, #1147 — can't re-include that way). Validated with `docker build --no-cache --target build`: COPY resolves, `nx run platform-frontend:build` ✓. First fix attempt (drop prettier from the COPY) was wrong — symptom only, error walked to the next file; **local `--no-cache` validation caught it before a 2nd red main.**

The sync then exposed THREE runtime bugs that ALL static gates (lint/typecheck/helm-unittest/trivy) + pod-health passed:

1. **nginx CrashLoopBackOff (#1477, merged)** — `apps/platform-frontend/nginx.conf` had an UNQUOTED regex with a `{8,}` brace quantifier (`location ~* \.[0-9a-fA-F]{8,}\.(?:js|css...)$`). **GENERAL LESSON: nginx's config parser treats `{`/`}` as block delimiters, so any regex containing a brace quantifier (`{n,}`) MUST be quoted or nginx exits with `[emerg] unknown directive`.** Doubly-dead: the charset/separator were also wrong (hex+dot vs Vite's real hyphen+base64url `assets/index-XvITPmWj.js`). Fixed BOTH with a `location ^~ /assets/` PREFIX match (no regex, no brace pitfall, no hash-charset assumption). Verify any baked-in nginx.conf with `docker run <base-image> nginx -t` mounting the conf.
2. **SPA unreachable — NetworkPolicy blocked Traefik (#1477 frontend, #1478 platform-base/gateway, both merged).** **GENERAL LESSON (platform-wide, was latent ~1 month): the `allow-ingress` netpol only admitted `app.kubernetes.io/part-of=platform` sources — but the Traefik controller (ns `traefik-system`, pod label `app.kubernetes.io/name=traefik`, NOT hostNetwork) carries NO part-of=platform label, so Calico (enforcing CNI) silently dropped Traefik→pod. Pod stays Ready (kubelet probes are node-sourced, netpol-exempt) so every gate is green while the site is dark (499/502/504).** Platform had NEVER served real browser traffic through Traefik (only pod-to-pod/pact). Fix = an explicit allow rule matching Traefik by `kubernetes.io/metadata.name: <networkPolicy.traefikNamespace=traefik-system>` + `app.kubernetes.io/name: traefik` on the service port. In platform-base it's **gated on `.Values.ingress.enabled`** (same flag as the IngressRoute) so it's COUPLED — a Traefik-routed service can't deploy without the allowance (recurrence-proof); renders only for the gateway today. `values.schema.json` is `additionalProperties:false` → any new `networkPolicy.*` value must be declared there or `helm template` fails.
