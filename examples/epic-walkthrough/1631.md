# Task: Command-endpoint completeness for the remaining lifecycle transitions

## Description

Close the gap between the specified API surface and the as-built one — every lifecycle transition should have a command endpoint, and five do not. Each is a small, well-understood shape: a partial-revert command on one aggregate, an edit command constrained to the initial editable state, an explicit create for the parent aggregate, a lightweight summary read alongside the existing detail read, and two optional contact references on a child (migration + DTO + ownership validation, which closes the confirmed design/backend gap). Covers FR-11, FR-12.

## Acceptance Criteria

- [ ] Partial revert: the command reverts only the children still eligible to be reverted and leaves the rest untouched; the parent's derived status is re-derived; the write is refused under the tenant write policy and while the parent is locked (AC: 1)
- [ ] Edit command: initial editable state only; a record past that point → 409 `INVALID_STATUS_TRANSITION`; refused under the tenant write policy (AC: 2)
- [ ] `POST /api/v1/deals`: creates an empty deal with a sequential per-tenant human-facing number, permission `deal:create`, emits `trading.deal.created` (AC: 3)
- [ ] `GET /api/v1/deals/:id/summary`: returns the summary object only (same numbers as the detail read; cached/live semantics unchanged) (AC: 4)
- [ ] Contact references: fields persisted + returned; a contact that does not belong to the record's own customer → 400 `VALIDATION_ERROR`; fields optional (AC: 5)
- [ ] All new writes respect the parent lock, the tenant write policy, RBAC decorators, and activity recording (AC: 6)
- [ ] Deal detail DTO exposes `lockedByName` (ADR-0064 resolver reuse, best-effort nullable); `DEAL_LOCKED` error details include `lockedByName` + `lockedAt` — feeds the FE "Locked by …" copy (AC: 7)

## Technical Details

- The revert command mirrors the equivalent command that already exists on the sibling aggregate; one outbox/activity write per transition per existing conventions.
- `POST /deals` reuses `DealService.create` + `deal-sequence.service.ts` (FOR UPDATE increment) — no new numbering logic.
- Contact-reference migration `Migration_008_haulage_contacts` (renumber to next free); DTO validation joins contact ownership via the existing customer-module queries.
