# Task: Inventory consumer idempotency (inbox + redelivery metrics)

## Description

Retrofit inventory-service's eight `trading.#` handlers with the ADR-0068 inbox: a `processed_event` insert in the same transaction as each stock effect, so RabbitMQ redelivery never double-applies movements or reservations. Add redelivery counters. The reconciliation job demotes to backstop. Covers FR-4.

## Acceptance Criteria

- [ ] `processed_event` table (inventory schema) + migration; PK (`consumer`, `event_id`) (AC: 1)
- [ ] All 8 handlers on the inbound `trading.#` topic dedup via one shared wrapper — duplicate delivery acks without re-applying (AC: 2)
- [ ] Redelivery counter metric `acme_inventory_consumer_redeliveries_total{consumer,event_type}` increments on dedup hit (AC: 3)
- [ ] Double-dispatch tc spec per handler family passes; a duplicate delivery produces a single stock effect (AC: 4)
- [ ] No behaviour change on first delivery (existing tc + pact suites stay green) (AC: 5)

## Technical Details

- `src/stock/inbox/` — processed-event entity/repo + `withInbox(consumer, eventId, fn)` wrapper used by `trading-event-consumer.ts` routing switch.
- Same table shape as trading (ADR-0068 reference implementations must match).
- Migration `Migration_003_inbox` (inventory schema).
